対象は、gh の認証ユーザーが作成した PR に、同じユーザーが付けた PENDING のコメントだけ。始める前に、ローカルのブランチを PR の head と照合する。報告は未解消の論点と判断が要ることだけ（解消済み・段取り・通った確認は書かない）。

## 対応

- 内容が明確で直し方が一意なものだけ直す。それ以外は見解・逆提案・反論をこのセッションで返す。
- コメントは目についた箇所への例示。PR の差分の中で、同じ直し方を当てるべき他の箇所も対象にする。
- インデックスに触れない。ユーザーは納得した修正から stage して受け入れる。

## 解消と削除

- コメントに対応する修正が全て stage されたら解消。一部だけなら未解消。回答だけのコメントはユーザーの了承で解消。
- 解消したコメントは、一覧を取り直してから ID を指定して消す。

## 全て解消したら

指示を待たずに、stage された内容で履歴を整えて force push する。

- 1 コミットの PR は amend。複数なら、その変更が最初に成立するコミットへ fixup して autosquash する。メッセージは変えない。
- 先に fetch し、リモートにだけあるコミットは上書きせずに取り込む。
- 書き換え後のツリーが承認済みの内容と一致し、対象外のコミットが変わらず、各コミットで CI と同じ検査が通ることを確かめる。この PR の上に積まれたブランチがあれば載せ直して同じく確かめる。
- 確かめた SHA を指定した `--force-with-lease` で push し、CI を確認する。
